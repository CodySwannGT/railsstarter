Official primary documentation checked live 2026-10-03:

- Reusable workflow syntax and permissions: https://docs.github.com/en/actions/how-tos/reuse-automations/reuse-workflows and https://docs.github.com/en/actions/reference/workflows-and-actions/reusing-workflow-configurations . Cross-repository reusable callers belong at jobs.<id>.uses, with declared workflow_call inputs matching types. Full commit SHA pins are the stable reviewable choice. Permission levels cannot increase through the called-workflow chain. Caller context/token are inherited; grants must satisfy each called workflow without granting unrelated privileges.
- Repository pin policy: https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/enabling-features-for-your-repository/managing-github-actions-settings-for-a-repository . Required full-length action SHA policy applies to actions; reusable tags can remain supported by GitHub policy, but this leaf should still use coherent immutable reusable revisions under Lisa/project policy. Inspect actual repository settings before proposing policy changes.
- Events: https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule and #workflow_dispatch . Scheduled runs operate on the default branch and require the definition there. Dispatchable definitions must also exist on the default branch. Therefore a feature-branch static parse or a PR run cannot demonstrate an actual retained schedule. PR proof and subsequent default-branch schedule proof are separate acceptance boundaries. Do not enable autonomous worker schedules merely to obtain proof; retain only a genuinely supported intended schedule and qualify workers through Lisa's declared epoch before any future activation.
- Run identity: https://docs.github.com/en/rest/actions/workflow-runs . Capture actual run id, event, path, run_attempt, status, conclusion, head_sha, head_branch, check_suite_id, timestamps and returned referenced_workflows when available. Match the PR identity and tested Git merge/head boundary explicitly; do not equate a historical green with the new PR artifact.
- Jobs: https://docs.github.com/en/rest/actions/workflow-jobs . Exhaust jobs pagination and preserve job ids/names/conclusions, non-empty steps and test-step execution. Retrieve the intended run attempt, not an arbitrary latest run. Logs/artifacts must name authored meaningful examples and report nonzero execution. A nonzero job count alone cannot prove those examples ran.
