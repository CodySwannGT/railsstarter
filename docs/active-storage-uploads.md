# Durable user uploads

Staging and production use the real Active Storage S3 service. Configure `ACTIVE_STORAGE_S3_REGION` and the selected environment's bucket variable: `ACTIVE_STORAGE_STAGING_BUCKET` or `ACTIVE_STORAGE_PRODUCTION_BUCKET`. Provision distinct private upload buckets for these environments. Development and test retain their existing Disk services and do not need S3 settings.

Normal deployed boot rejects absent, empty or whitespace-only bucket/region settings with `UploadStorage::ConfigurationError`. Disabling `AWS_BOOTSTRAP_ENABLED` does not change storage selection. Access errors propagate to the caller without falling back to Disk. Active Storage uploads after committing attachment metadata, so a denied upload can leave blob/attachment rows. Reconcile or retry those rows deliberately. An error does not imply a rolled-back attachment.

The host migration was generated by the installed Active Storage 8.1.4 `active_storage:install` task, from engine migration `20170806125915_create_active_storage_tables.rb`, then refactored into private table helpers. It retains the generated Migration[7.0] types, precision, indexes, foreign keys and reversibility and adds only blobs, attachments and variant records. Apply the primary migration with `bin/rails db:migrate:primary` using the application's established safe migration procedure. The primary schema includes no witness/business table. Consumer models can declare `has_one_attached` or `has_many_attached` after these metadata tables exist.

The YAML contains no static credentials, profile, endpoint override, public ACL or invented prefix option. At runtime the AWS SDK uses its standard credential provider chain. ECS task-role identity is deployment policy, rather than an identity enforced by omitting keys from this YAML. Supply the application ECS task role, separately from the task execution role and deployment/asset publication identity. Earlier credential sources can take precedence, so deployment configuration must omit competing credential sources and verify the actual role independently.

Grant `s3:ListBucket` on the exact upload bucket ARN and `s3:GetObject`, `s3:PutObject`, `s3:DeleteObject` on its object ARN (`arn:aws:s3:::<upload-bucket>/*`). Do not grant all S3 actions, public ACL writes or unrelated asset-bucket access. Bucket/prefix conditions must match actual object keys. This starter uses distinct buckets and does not prepend keys. KMS encryption or multipart workloads can require additional permissions that the tiny single-part acceptance fixture does not prove. Provisioning and real IAM/provider validation remain deployment responsibilities.

User uploads and compiled asset publication are separate. The exact `SECRET_KEY_BASE_DUMMY=1 bin/rails assets:precompile` task selects an inert build-only Active Storage adapter, constructs no provider client and refuses every upload/read operation. A dummy secret in any other task or normal process does not exempt deployed storage validation. Asset compilation requires no deployment bucket or credentials and never falls back to Disk.

## Local acceptance

Run `bundle exec rspec spec/storage` with the supported Ruby/Bundler dependencies, Python 3 and a reachable local Docker daemon. The exact preinstalled MySQL 8.4.11 image digest is `sha256:6ea90827b1100f8f2ae306a539f86d2c264a26ed435a2a9f75551dd5c3aeb242`. Missing access fails the suite rather than skipping it. No private environment manifest is required by the regression suite and no provider request is allowed.

The self-provisioning fixture creates nonce-owned containers, volumes, loopback ports and four strictly scoped test databases. It checks physical server identity, every resolved database role and grants before Rails/schema access. A fixture-only owner attaches actual bytes through the real S3 adapter with stateful SDK callbacks. A second independent process/root retrieves the same committed metadata after the first process exits and its local storage is replaced. Only bytes actually supplied to `put_object` are stored for `get_object`.

The same suite compares actual fresh metadata schema dumps from the locked engine and host migration and performs a down/up roundtrip in owned fresh state. It observes AccessDenied metadata honestly, absent/blank configuration errors, actual credential-free asset tasks and local/test parsing. Disk mutation, missing objects and corrupt objects falsify the real persistence detector. Exact command logs/results and hashes are retained in an ignored mode-0700 `tmp/active-storage-evidence-*` directory with mode-0600 files. Application scratch, containers, volumes and owned ports are positively cleaned. These local stubs do not establish deployed S3 durability, IAM grants or live-provider behavior. A separate empirical verifier must review the frozen builder evidence.
