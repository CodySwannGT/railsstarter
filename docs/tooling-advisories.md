# Tooling dependency dispositions

Rechecked on 2026-10-09 with Node 22.23.3, npm 10.9.9, Bun 1.3.8 and the integrity-qualified published Lisa 4.73.2 package. The starter is a private Rails application. Lisa is development tooling; the temporary updater qualification fixture is also a development dependency. These packages are absent from the production Docker dependency installation.

The initial recheck reported 35 affected entries, including critical Handlebars findings in the stale 4.7.9 selection. Lisa 4.73.1 already declares the patched 4.7.10 floor. A targeted native npm update selects 4.7.10, and Bun's native npm-lock import reconciles the second lock without an override or a new direct dependency. Both frozen installers passed with manifest and lock bytes unchanged. A synthetic AST injection executed with 4.7.9 and was rejected with 4.7.10 under both installers; ordinary string templates still rendered. This proves the library primitive and its repair, not an externally reachable Rails exploit. The patched [AST type-confusion](https://github.com/advisories/GHSA-8r5x-fm3f-whwj), [own-property bypass](https://github.com/advisories/GHSA-p8wg-vrv2-v86f) and [inline embedding](https://github.com/advisories/GHSA-xw65-4hp5-5hc7) advisories no longer appear in the audit.

After that compatible repair, `npm audit --ignore-scripts` reports 34 affected entries: 11 high and 23 moderate, with zero critical entries. These propagate the five remaining underlying advisories through the tooling graph. The audit exits nonzero and must remain visible. Its proposed forced change downgrades Lisa to 4.55.0 and is not an acceptable repair.
